The everyday command, and the default: it generates a full set of pgTAP tests for every function and trigger, runs them, and measures how much of each routine they exercised.

Get started Back to overview

What it generates

Per function: valid inputs, low and high boundaries, one test per branch on both its true and false side, result-set shape, and rows matching the recorded output. Triggers are tested by behaviour - it fires the INSERT, UPDATE or DELETE and asserts what the trigger actually did, or the error it raised. All of it is standard pgTAP you commit next to your code and run with runtests() or pg_prove.

Every uncovered line is explained

Coverage is measured by actually running the tests, not estimated. Rather than leave a line simply red, the report tags each uncovered line so you know whose problem it is.

Dead code (D)

The line can never run, sometimes with the exact contradictory conditions named. Usually points at a real bug.

Error-recovery (H)

Inside an exception handler that valid data cannot reach. Untested by default, by design; you can opt in.

Tool limit (E)

No evidence of dead code; the tool could not produce a test for this line. An honest gap, reported plainly.

When a branch cannot be tested reliably it is reported NOT_TESTABLE with a plain reason, never faked into a green pass.
