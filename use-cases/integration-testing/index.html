Available for PostgreSQL - Team edition

The whole flow inside the database,
tested on every build.

A unit test proves one routine in isolation. QA needs more: the function, the functions it calls, and the triggers its writes fire, all running together on real rows, the way production runs them. UnitAutogen generates that too, from the same code, with no scenarios written by hand.

See integration testing Team edition

What QA gets

End-to-end runs

Each entry point is exercised with the routines it calls and the triggers it fires left in place, not mocked, so the test sees what production sees.

Coverage across the call map

Line and branch coverage reported for the root and everything it reaches, so a branch inside a trigger three calls deep is not invisible.

A regression suite you did not write

Today's behaviour is captured as tests. A change anywhere in the flow that alters an outcome fails the build with the exact routine and branch named.

Unit and integration together

Developers run the unit tests on their own routines while they work. QA runs the integration suite against the assembled database on every build. Both come from the same generator, so there is one set of seed data, one report format, and one place a failure points to.

Integration testing is part of the Team edition; unit testing and coverage are free in the Community Edition.
