Available for PostgreSQL

Prove your database
actually isolates tenants.

Most PostgreSQL apps that hold more than one customer's data rely on Row-Level Security and careful function logic to keep tenant A from ever seeing tenant B. The problem is proving it stays true as the code keeps shipping.

seccover, in the engine rlsautotest, free

Two ways in

seccover, in the PostgreSQL engine, exercises your functions, views and triggers as different tenants and reports, per routine, whether isolation is enforced or leaking, with the evidence and the exact tables and channel a leak reaches. A --pii pass catches personal data escaping through error and RAISE messages.

rlsautotest, free and open source, works from your Row-Level Security policies directly: it generates pgTAP tests, and the seed data, that prove who can read and write which rows, per table, per command, per identity, and fails CI if a table has no policy at all.
